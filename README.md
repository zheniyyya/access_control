# Моделювання системи розмежування доступу до інформаційних ресурсів підприємства

Десктопний застосунок для курсової роботи (варіант №7). Він будує рольову модель доступу (RBAC)
підприємства: 20 користувачів, 4 ролі, 6 інформаційних ресурсів. Далі застосунок виявляє надлишкові
й небезпечні права, будує модель мінімальних привілеїв зі службових функцій ролей, порівнює обидві
моделі та моделює запити доступу й компрометацію облікових записів. Результати можна експортувати
в Excel і Word для пояснювальної записки; висновки, сформовані з обчислених чисел, входять у звіт Word.

## Вимоги

- Windows 10/11;
- Python 3.11 або новіший (перевірено на Python 3.14).

## Встановлення

```bat
cd access_control
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

> **Увага:** середовище `.venv` має створювати Python 3.11+ з python.org. Якщо в системі є ще
> інший Python (наприклад, з MSYS2 у `C:\msys64`) і він стоїть у `PATH` першим, команда `python`
> запустить саме його. Тоді бібліотеки не знайдуться (`No module named 'PySide6'`). Перевірити, який
> Python запускається, можна командою `python --version`; за потреби вкажіть повний шлях:
> `C:\Users\<користувач>\AppData\Local\Python\pythoncore-3.14-64\python.exe -m venv .venv`.

## Запуск

```bat
python main.py
```

Під час запуску застосунок завантажує вихідні дані варіанту №7 з `data/variant7.json`.
Якщо файл пошкоджено, програма покаже повідомлення і запропонує відкрити інший файл моделі.

## Тести

```bat
pytest
```

Тести (`tests/`) перевіряють усі контрольні значення варіанту (розділ «Контрольні значення» нижче),
правила аналізу, оптимізацію, ризики, збереження моделей, експорт в Excel і Word, а також GUI.
GUI-тести працюють без показу вікон, на платформі Qt `offscreen`.

## Збирання .exe (PyInstaller)

```bat
pyinstaller --noconfirm --windowed --name AccessControl --add-data "data;data" main.py
```

Результат з'явиться в теці `dist\AccessControl\` (близько 300 МБ). Запускається файл
`AccessControl.exe`, а для перенесення на інший комп'ютер копіюється вся тека.

Перевірка зібраної програми без участі користувача:

```bat
dist\AccessControl\AccessControl.exe --self-test
```

Самоперевірка будує всі вкладки, експортує Excel, Word і рисунки у тимчасову теку та завершується
з кодом 0 (успіх) або 1. Поруч з `.exe` вона записує журнал `self_test.log`.

Шляхи до файлів даних обчислює функція `app.paths.resource_path()`. Вона враховує `sys._MEIPASS`,
тож `data/variant7.json` знаходиться і після збирання.

## Робота з програмою

Панель інструментів містить кнопки «Відкрити модель», «Зберегти модель», «Скинути до варіанту 7»,
«Експорт у Excel», «Звіт Word», «Зберегти діаграми», а також «Скасувати» і «Повторити» (Ctrl+Z / Ctrl+Y).
Рядок стану показує ключові числа: дозволені операції до і після оптимізації, кількість надлишкових
прав і захищеність критичних ресурсів (подробиці — у підказці при наведенні). Між вкладками можна
перемикатися клавішами Ctrl+1 … Ctrl+7. Пояснення до стовпців і кнопок показуються у спливних підказках.

| Вкладка | Призначення |
|---|---|
| 1. Вихідні дані | Таблиці користувачів, ресурсів (K, ознака критичності), ролей і операцій; редагування з перевіркою даних. |
| 2. Структурна схема | Користувачі (за ролями) → Ролі → Ресурси. Перемикач «Початкова / Оптимізована», підсвічування зв'язків під курсором, масштаб коліщатком, експорт у PNG (2×) і SVG. |
| 3. Початкова матриця | Матриці ролей (4×6) і користувачів (20×6), кольори за найнебезпечнішою операцією, позначки індивідуальних дозволів. Клацання по клітинці відкриває діалог із чотирма прапорцями: режим «що буде, якщо». |
| 4. Аналіз ризиків | Знахідки з фільтрами за рівнем, ресурсом і роллю (кольорові лічильники рівнів теж фільтрують); ризик і захищеність ресурсів; рейтинг; діаграма індексу ризику. |
| 5. Оптимізація | Службові функції ролей (редаговані), кнопка «Побудувати модель мінімальних привілеїв», оптимізована матриця, матриця змін, обґрунтування клітинок; принципи моделі — кнопка «Принципи…». |
| 6. Порівняння | Порівняльна таблиця «Початкова / Оптимізована / Зміна / Зміна, %» і діаграми «до / після» та теплові карти. |
| 7. Моделювання | Перевірка запиту доступу («ДОЗВОЛЕНО / ЗАБОРОНЕНО» з поясненням) і сценарій компрометації облікового запису («радіус ураження»). |

Будь-яка зміна моделі (довідники, клітинки матриць, службові функції) одразу перераховує всі показники.

### Експорт

- **Excel** — 9 аркушів: «Користувачі», «Ресурси», «Початкова матриця (ролі)», «Початкова матриця
  (користувачі)», «Надлишкові права», «Оптимізована матриця (ролі)», «Оптимізована матриця (корист.)»,
  «Порівняння», «Ризики». Кольори клітинок такі самі, як у GUI, і задані ще й умовним
  форматуванням, тож після редагування літер в Excel колір оновлюється. Заголовки закріплено,
  ширину стовпців підібрано за вмістом. Excel обмежує назву аркуша 31 символом, тому в назві
  сьомого аркуша «користувачі» скорочено до «корист.».
- **Word** — звіт із розділами 2.1–2.6 відповідно до завдань: структурна схема, початкова матриця,
  надлишкові права (зведення за рівнями і повна таблиця), оптимізована матриця з обґрунтуванням,
  порівняльна таблиця й діаграми, висновки. Оформлення: Times New Roman 14 пт, інтервал 1,5, підписи
  «Таблиця 2.1 – …» і «Рисунок 2.1 – …», таблиці з рамками, шрифт таблиць 12 пт.
- **Зберегти діаграми** — у вибрану теку записуються 4 діаграми (PNG, 200 dpi) і дві структурні
  схеми (PNG 2× та SVG).

## Архітектура

Архітектура шарова. Доменна логіка й розрахунки не залежать від Qt: це чисті функції, які
тестуються без GUI. GUI лише викликає їх і відображає результат. Глобального стану немає: поточна
модель і результат аналізу зберігаються в об'єкті `ModelState`, яким володіє головне вікно.

```

├── main.py                  # точка входу; --self-test — перевірка збірки

├── app/

│   ├── palette.py           # єдина палітра: GUI, діаграми, Excel, Word
│   ├── domain/

│   │   └── seed.py          # завантаження / скидання до варіанту 7
│   ├── services/            # чисті функції розрахунків (без Qt)
│   │   ├── matrix.py        # матриці ролей і користувачів, ефективні права, підрахунки
│   │   ├── analyzer.py      # правила П1–П9, знахідки, надлишкові клітинки ролей

│   │   ├── conclusions.py   # висновки з обчислених чисел
```

### Формули та правила

- Вага операцій: Ч = 1, З = 2, Р = 3, В = 4.
- Ефективні права користувача = права ролі ∪ індивідуальні дозволи.
- Ризик(r) = K(r) × Σ по всіх користувачах Σ ваг дозволених операцій на r;
  Max(r) = 20 × 10 × K(r); Z(r) = (1 − Ризик / Max) × 100 %, округлення до 0,1.
  Оцінка: Z ≥ 80 % — високий рівень, 50–80 % — середній, < 50 % — низький.
- Знахідка — трійка (користувач, ресурс, операція), що є в початковій моделі, але відсутня в моделі
  мінімальних привілеїв. Рівень небезпеки — максимум серед правил П1–П9.
- Модель мінімальних привілеїв: права ролі = об'єднання операцій її службових функцій,
  індивідуальних дозволів немає.

### Файл моделі (JSON)

Ключі верхнього рівня: `format_version`, `name`, `resources`, `roles` (зі службовими функціями
`functions`), `users`, `initial_model` (`role_permissions`, `user_grants` з причиною надання),
`rule_bindings`, `principles`. Операції записуються літерами: `"ЧЗРВ"`, `"Ч–РВ"`, `"–"`.
Некоректний JSON або відсутні поля дають зрозуміле повідомлення про помилку, програма при цьому
не падає.
